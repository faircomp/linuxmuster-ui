## Engine (T1) — 1.6↔2.0 byte-logisch identisch, kein Port nötig

`MigrationService.runMigrations(model, list)` (`main.js:2676`) ist die einzige Engine:

- **Typ:** `Migration<T> = { name: string, version: number, execute(model): Promise<void> }`
  (Objekt-Literale, keine Klassen).
- **Ablauf:** sequentielles `list.reduce((p, m) => p.then(() => m.execute(model)), Promise.resolve())`
  — Migrationen laufen **in Array-Reihenfolge, streng seriell**.
- **Wiring:** pro Modell **ein** `runMigrations`-Aufruf im `onModuleInit` des jeweiligen Service
  (11 Aufrufe, s. u.).
- **Idempotenz-Muster:** jede `execute` filtert `model.find({ schemaVersion: <prev> })` → transformiert
  die Treffer → `set({ schemaVersion: <new> })`. **Leere Treffermenge = No-Op** → gefahrlos
  wiederholbar. Die erste Migration je Modell (`000-*`) nutzt `prev = undefined` (Dokumente ohne
  `schemaVersion`).
- **Kein `down()`** — forward-only (s. Guardrails in `upgrade-1.6-to-2.0.md`).

**Verifikation (T1):** `grep -c '\.runMigrations(' main.js` == **11**; die `reduce`-Logik in
`main.js:2677–2684` ist identisch zu `apps/api/src/migration/migration.service.ts` (1.6) → **Engine
wird nicht portiert, nur wiederverwendet.**

## Zähl-Korrektur ins Tracking (T7)

**PLAN §3.3 stand: „12× `runMigrations`, 32 Migrationsnamen".** Korrekt gezählt:
- **11** `runMigrations`-Wirings (nicht 12 — der 12. `runMigrations`-Grep-Treffer ist die
  Engine-Methoden-**Definition** `main.js:2676` selbst, kein Wiring).
- **38** Mongoose-Migrationen über 11 Modelle **+ 6** Keycloak-Skripte = **44** Namensliterale
  (2.0.200), **33** im 1.6-Repo.

**Ursache des Under-Counts (32):** (1) lowercase-only-Grep übersah die camelCase-Keycloak-Namen und
(2) die `const name = '…'`-Form (statt `name: '…'`) einiger Migrationen. **Gegen-Fehler beim naiven
Fix:** ein Muster, das die Quotes **mit** matcht und dann `sort -u` zählt, **über-zählt auf 49** —
5 Namen kommen sowohl einfach- als auch doppelt-gequotet vor und werden doppelt gezählt. **Korrektes
Tracking-Grep-Muster** (für `fingerprint.sh`, [[openedulution-fork-plan]]-Tracking-Pipeline) muss die
Quotes **normalisieren** (zweiter `grep -oE` strippt sie vor `sort -u`):

```
grep -ohE "['\"][0-9]{3}-[A-Za-z0-9-]+['\"]" <src> | grep -oE "[0-9]{3}-[A-Za-z0-9-]+" | sort -u | wc -l
```

ergibt **44** in `main.js` und **33** im 1.6-Repo (Verify T7, quote-normalisiert) — deckungsgleich mit
dem `name:`/`const name =`-verankerten Set (Gegenprobe `comm` beidseitig leer). Ohne den
Quote-Strip-Schritt liefert dasselbe Muster fälschlich 49. Damit zählt das Fingerprint künftige
Migrationen zuverlässig (beide Namensformen, keine Quote-Doppelzählung).
